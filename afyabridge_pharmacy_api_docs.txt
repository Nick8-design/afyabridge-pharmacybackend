OVERVIEW
--------
This document describes every API endpoint consumed by the AfyaBridge Pharmacy
Portal frontend. Each section lists the HTTP method, exact URL path, request
payload (if any), and the exact response shape the frontend expects.

The frontend connects directly to this backend. No proxy is used.

All endpoints except those listed as PUBLIC require a Bearer token:
  Authorization: Bearer <access_token>


STANDARD RESPONSE ENVELOPE
---------------------------
Every response — success or error — must follow this envelope:

  {
    "success": true | false,
    "message": "Human-readable message",
    "data": { ... } | [ ... ] | null,
    "errors": { "field": ["error msg"] } | null
  }

Paginated list responses wrap inside data:

  {
    "success": true,
    "data": {
      "count": 42,
      "next": "http://.../api/orders/?page=2",
      "previous": null,
      "results": [ ... ]
    }
  }

HTTP Status Codes used:
  200 OK            — success, data returned
  201 Created       — resource created
  400 Bad Request   — validation error or business rule violation
  401 Unauthorized  — missing or invalid token
  403 Forbidden     — authenticated but not permitted
  404 Not Found     — resource does not exist
  500 Server Error  — unexpected server error


================================================================================
  1. AUTHENTICATION
================================================================================

All auth endpoints are PUBLIC — no token required.

--------------------------------------------------------------------------------
POST /auth/login/
--------------------------------------------------------------------------------
Description: Authenticate a pharmacy user and receive tokens.

Request Body (JSON):
  {
    "email": "pharmacist@afyabridge.com",   // required
    "password": "Password123!"              // required, min 8 chars
  }

Response 200 OK:
  {
    "success": true,
    "message": "Login successful",
    "data": {
      "access_token": "<jwt>",
      "refresh_token": "<jwt>",
      "user": {
        "id": "uuid",
        "email": "pharmacist@afyabridge.com",
        "full_name": "Kevin Rutto",
        "phone_number": "+254712345678",
        "role": "pharmacist",
        "pharmacy_id": "uuid",
        "account_status": "active",
        "is_active": true
      }
    }
  }

Response 400 (wrong credentials):
  {
    "success": false,
    "message": "Invalid email or password",
    "data": null,
    "errors": null
  }

Notes:
  - The frontend stores access_token and refresh_token in localStorage.
  - The frontend reads user.pharmacy_id to determine if the account is linked
    to a pharmacy. If pharmacy_id is null or missing the dashboard shows a
    "not linked" warning.
  - Tokens expire after 60 minutes. The frontend will re-login on 401.


--------------------------------------------------------------------------------

    "errors": null
  }

================================================================================
  2. PHARMACY REGISTRATION
================================================================================

The frontend collects all registration data across a multi-step UI form and
sends everything in a SINGLE request to this one endpoint. No step-by-step
endpoints are needed.

--------------------------------------------------------------------------------
POST /auth/register/complete/
--------------------------------------------------------------------------------
Description: Register a new pharmacy and create the pharmacist account.
Auth: PUBLIC
Content-Type: multipart/form-data

Form Fields:

  PHARMACY / BUSINESS INFORMATION:
    pharmacy_name_legal     string   required  Legal registered name
    trading_name            string   optional  Brand/storefront name
    business_reg_no         string   required  e.g. PVT-ABC123
    kra_pin                 string   required  e.g. A012345678Z
    ppb_license_no          string   required  e.g. PPB/2024/1234
    license_expiry          date     required  Format: YYYY-MM-DD
    county                  string   required  Kenyan county
    sub_county              string   optional
    physical_address        string   required
    gps_lat                 number   optional  GPS latitude (6 decimal places)
    gps_lng                 number   optional  GPS longitude (6 decimal places)
    business_phone          string   required  Kenyan format e.g. 0712345678
    business_email          string   required  Valid email

  SUPERINTENDENT PHARMACIST DETAILS:
    pharmacist_name         string   required  Full legal name
    id_or_passport_no       string   required  National ID or Passport number
    pharmacist_reg_no       string   required  e.g. P/2024/12345
    practicing_license      string   required  e.g. P/2024/12345
    practicing_expiry       date     required  Format: YYYY-MM-DD
    pharmacist_phone        string   required
    pharmacist_email        string   required

  DOCUMENT UPLOADS (files):
    id_document             file     required  Superintendent ID/Passport (PDF/JPG/PNG max 5MB)
    practicing_license_doc  file     required  Practicing License document
    operating_license_doc   file     required  Pharmacy Operating License
    business_reg_cert       file     required  Business Registration Certificate
    kra_pin_cert            file     required  KRA PIN Certificate
    proof_of_address_doc    file     required  Utility bill or Lease agreement

  FINANCIAL / MPESA SETUP:
    mpesa_method            string   optional  e.g. "PAYBILL"
    short_code_number       string   optional  Last 6 digits of M-Pesa number
    settlement_frequency    string   optional  "DAILY" | "WEEKLY" | "MONTHLY"

  ACCOUNT SECURITY:
    password                string   required  Min 8 chars, uppercase, number, symbol
    two_factor_enabled      boolean  optional  Default: true
    security_question       string   optional
    security_answer         string   optional

Response 201 Created:
  {
    "success": true,
    "message": "Pharmacy registered successfully. Welcome to AfyaBridge.",
    "data": {
      "access_token": "<jwt>",
      "refresh_token": "<jwt>",
      "user": {
        "id": "uuid",
        "email": "pharmacist@afyabridge.com",
        "full_name": "Kevin Rutto",
        "role": "pharmacist",
        "pharmacy_id": "uuid"
      }
    }
  }

Notes:
  - On success the frontend immediately logs the user in using the returned
    tokens and redirects to /dashboard. No separate login step is needed.
  - If registration succeeds but approval is required before the account is
    fully active, return pharmacy_id in the user object but set
    account_status to "pending_approval". The dashboard will show a
    "not linked" / pending state.

Response 400 (validation error):
  {
    "success": false,
    "message": "Registration failed. Please review your details.",
    "data": null,
    "errors": {
      "business_reg_no": ["This registration number already exists."],
      "kra_pin": ["Invalid KRA PIN format."]
    }
  }


================================================================================
  3. ORDER MANAGEMENT
================================================================================

Orders are the core module of the pharmacy portal. A pharmacy user manages
orders from creation through to delivery or direct dispensing.

Order Lifecycle:
  pending → processing → ready → delivered   (pickup: patient collects in store)
  pending → processing → ready → dispatched  (delivery: rider assigned)
  Any status except delivered/dispatched → cancelled

--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
Description: List all orders for the authenticated pharmacy.
Auth: Required

Query Parameters:
  status      string   optional  pending | processing | ready | dispatched |
                                 delivered | cancelled
  priority    string   optional  normal | urgent
  q           string   optional  Search by patient name (case-insensitive)
  page        integer  optional  Default: 1
  page_size   integer  optional  Default: 20, max: 100

Response 200 OK:
  {
    "success": true,
    "data": {
      "count": 12,
      "next": "/api/orders/?page=2",
      "previous": null,
      "results": [
        {
          "id": "uuid",

POST /orders/{order_id}/dispense/
--------------------------------------------------------------------------------
Description: Dispense an order directly to a patient who walks in (pickup).
Auth: Required

Prerequisites:
  - Order status must be "ready"
  - Order delivery_type must be "pickup"
  - Sufficient inventory must exist for each item

Path Parameter:
  order_id   uuid   required

Request Body (JSON):
  {
    "instructions": "Take with food after meals"   // optional
  }

What happens on success:
  1. Inventory quantity decreases for each drug in the order
  2. Order status changes to "delivered"
  3. Dispensing record created

Response 200 OK:
  {
    "success": true,
    "message": "Order dispensed successfully to Victoria Atieno",
    "data": {
      "order_id": "uuid",
      "order_number": "ORD-3B6CB08A",
      "patient_name": "Victoria Atieno",
      "status": "delivered",
      "items_dispensed": 1,
      "dispatched_records": [
        {
          "drug_name": "Amoxicillin 500mg",
          "quantity": 21,
          "dispensed_at": "2026-04-07T14:30:00Z"
        }
      ]
    }
  }

Response 400 (order not ready):
  {
    "success": false,
    "message": "Order must be \"ready\" to dispense. Current status: processing",
    "data": null,
    "errors": null
  }

Response 400 (insufficient stock):
  {
    "success": false,
    "message": "Insufficient stock for some items",
    "data": null,
    "errors": {
      "stock_errors": [
        "Amoxicillin 500mg: need 21, only 5 in stock"
      ]
    }
  }

POST /deliveries/{delivery_id}/confirm/
--------------------------------------------------------------------------------
Description: Confirm delivery using the OTP code provided by the patient.
Auth: Required

Path Parameter:
  delivery_id   uuid   required

Request Body (JSON):
  {

  }

What happens on success:
  1. Delivery status changes to "delivered"
  2. Linked order status changes to "delivered"
  3. delivered_at timestamp is recorded

Response 200 OK:
  {
    "success": true,
    "message": "Delivery confirmed successfully",
    "data": {
      "delivery_id": "uuid",
      "order_id": "uuid",
      "status": "delivered",
      "delivered_at": "2026-04-07T15:45:00Z"
    }
  }

Response 400 (wrong OTP):
  {
    "success": false,
    "message": "Invalid OTP code. Please check and try again.",
    "data": null,
    "errors": null
  }

================================================================================
  8. AUTHENTICATION & SECURITY RULES
================================================================================

Token Lifecycle:
  - Access token expires after 60 minutes.
  - Refresh token is used to get a new access token.
  - On 401 the frontend clears localStorage and redirects to /auth/login/.

401 Behaviour:
  The frontend only logs out on 401 if the error message indicates a real
  auth failure (contains "token", "credentials", or "authentication", or if
  the message is empty). A 401 with message "Your account is not linked to a
  pharmacy" will NOT trigger auto-logout — it is treated as a business error
  and shown as an error message in the relevant component.

  IMPORTANT: Do NOT return 401 for business logic errors like "pharmacy not
  linked". Use 400 for those cases to avoid unintended logouts.

Pharmacy Linking:
  - A pharmacist account can exist without being linked to a pharmacy.
  - profile.pharmacy_id being present means the account is linked.
  - Endpoints like /orders/, /inventory/, /deliveries/ should return 400
    (not 401) with message "Your account is not linked to a pharmacy"
    when the pharmacy is not yet approved/linked.
